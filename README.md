# Student team database

This repository is the migration and synthetic-review source of truth for the team database, linked to Supabase project `internship` (`fivopskfqvgyyjzsvabx`). The same 50 fictional users now exercise every team module.

Current deployed scope:

- 51 repository-managed application tables across `core`, `safety`, `analytics`, and `audit`.
- All 51 repository-managed tables are populated with synthetic review data derived from users 1 through 50.
- Approved workbook catalogs are loaded in full: 962 interests, 100 prompts, 110 connection intents, 219 safety taxonomy pairs, 38 notification categories, and 41 connection-close reasons.
- Automatic seeding remains disabled; the lead applies the reviewed full-team fixture explicitly.
- User business IDs are UUIDv4 values. New IDs are generated by `extensions.gen_random_uuid()`; authorization must still prevent IDOR because identifiers are not secrets.
- RLS on every application table. `anon` and `authenticated` have no application-schema access; the separate backend uses the trusted `service_role` path.
- A NOLOGIN `student_database_reviewer` role limited to sanitized views in the `review` schema.
- Atomic registration supports email OTP, phone OTP, Google, and Apple; verified identities can be linked to an existing user without duplicating contacts.
- OTPs have a 10-minute expiry, five-attempt lockout, 60-second resend cooldown, five resends per hour, contact-version binding, and account-recovery session revocation.
- Refresh tokens are stored only as 32-byte digests, rotated with reuse detection, and revoked automatically for suspended, deactivated, deletion-pending, or deleted accounts.
- Consent events reference an immutable policy catalogue containing the exact version, document URI, and SHA-256 content hash.
- Identity verification, contact, authentication identity, OTP, consent, registration, and session changes produce sanitized append-only audit events.

The 50 fictional users cover production-style identity, profile, catalog, discovery, connection, messaging, notification, background-job, moderation, analytics, and audit scenarios. Never load real Aadhaar, PAN, phone, email, message, or moderation data into this review project.

The fixture covers every account, overall-verification, contact-verification, Aadhaar-verification, PAN-verification, OTP status, OTP purpose, authentication provider/status, consent type/decision/source, gender, lifecycle actor, lifecycle reason, Aadhaar failure reason, and PAN failure reason allowed by Aditya's current constraints. State-dependent nulls are intentional and required.

For this fixed review dataset, the internal numeric identity columns have been normalized to start at 1. Production logic must still use UUID `user_id` and must not assume numeric identities are continuous; PostgreSQL sequences can legitimately contain gaps after failures, rollbacks, or deletions.

## Team workflow

The lead owns the deployed design. Teammates review the synthetic views and propose changes through GitHub. Never edit tables directly in the Supabase dashboard and never rewrite a deployed migration; add a new migration.

```powershell
cd C:\Users\Hp\Intern_DB\student-team-database
$env:PATH = 'C:\Program Files\nodejs;' + $env:PATH

# Rebuild deterministic catalog SQL after an approved workbook change
npm.cmd run seed:generate

# Rebuild Aditya's deterministic 50-user identity fixture
npm.cmd run seed:synthetic

# Rebuild the complete deterministic team fixture
npm.cmd run seed:team

# See pending schema changes without deploying them
npx.cmd supabase db push --remote --dry-run

# Lead-only schema deployment after review (does not seed data)
npx.cmd supabase db push --remote --yes

# Server-side SQL checks
npx.cmd supabase db lint --remote --level warning
```

The catalog generator asserts the exact workbook counts and stops if a source has drifted. These scripts verify the deployed contract and exercise the synthetic workflow in a rollback transaction:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-remote.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-synthetic.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-team-review.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\validate-identity-lifecycle.ps1
```

## Repository map

- `supabase/migrations/` — ordered schema, constraints, routines, RLS, and grants.
- `supabase/seed.sql` — generated reference catalogs from the reviewed workbooks.
- `supabase/synthetic_review_data.sql` — idempotent Aditya-only 50-user identity fixture.
- `supabase/full_team_review_data.sql` — generated, atomic full-team fixture for all 51 tables.
- `supabase/identity_lifecycle_review_data.sql` — deterministic session-state coverage for the existing 50 users.
- `supabase/tests/identity_lifecycle_contract.sql` — transactional behavior checks for registration, linking, OTP, sessions, lifecycle revocation, consent, and auditing.
- `scripts/generate-full-team-review.mjs` — rebuilds catalogs, identity data, and every team module from the same 50 users.
- `supabase/tests/schema_contract.sql` — table, catalog, and security assertions.
- `scripts/generate-seed.mjs` — deterministic workbook-to-SQL generator.
- `docs/review/` — source extraction, original analysis, inventories, and decision evidence.

The original review documents remain as an audit trail. Where they describe proposals or blockers, the deployed migrations and this README record the lead's final decision.
